## 账号管理与凭据提醒

一个实例最多添加 20 个账号，同一 V2EX 账号不能重复添加；替换 API Token 时仍须属于原账号。

通过侧栏「账号管理」查看所有已添加账号的启用状态、Token / Cookie 验证状态和错误，进入「连接与设置」更新凭据，或确认移除旧账号。移除会删除该账号的本地凭据、历史与推送队列，不删除 V2EX 网站账号，也不影响其他配置。删除后的账号不会在服务重启后恢复；备份中的副本需另行管理。

新建账号必须同时填写 API Token 和 Cookie，管理页与服务端均校验必填。前往 [V2EX Token 设置](https://v2ex.com/settings/tokens) 生成令牌，Scope 选择 Everything，有效期建议 180 天；可用 Scope 和有效期见 [官方 API 文档](https://www.v2ex.com/help/api)。Cookie 需包含 A2。添加时先选择环境变量代理、直连或自定义 HTTP/HTTPS 代理，再点击「验证并保存账号」。助手使用所选连接方式请求 `/api/v2/member`，将 `result.username` 与 Cookie 对应的首页顶栏用户名逐字比较（区分大小写）；完全一致且首页可正常读取后，才一起加密保存凭据和代理设置。若 API 身份验证成功但首页遇到 403 或 CF 挑战，会保存为待网页验证账号并暂停同步。尚未安装 browser 时，进入账号后按引导安装可选浏览器组件，再完成人工验证、配对并开启同步；无需重新填写凭据。其他验证失败、账号不匹配、请求取消或 API 额度冷却时不创建账号，修改表单或等待冷却后可重试。旧账号不被删除，未配置 Cookie 的会显示补充提示。

API 返回 Token 过期或失效时，工作台与账号管理显示更新提醒，暂停该账号的自动 API 请求；Cookie 返回未登录首页、登录跳转、401 或账号不匹配时，单独提示更新 Cookie，并暂停首页检查。网络失败、403 访问挑战或无法识别的页面显示访问错误并退避，不直接判为 Cookie 过期。两种问题独立保存，重启不清除；已验证过身份的账号在 Token 失效后仍会检查 Cookie，便于同时发现两项问题；更新对应凭据后重新验证，保留原推送基准、历史和冷却。

没有通知 API 请求的账号，每 24 小时用只读 `GET token` 检查 Token；正常通知请求成功会顺延这项检查。检查仍遵守账号与实例额度、Retry-After，Cookie 失效期间也可检查 Token。提醒以实际检查结果为准，不提供精确到期倒计时；暂停账号时停止后台检查。页面每五秒刷新已有检查状态，不因浏览页面额外请求上游。

## 配对接收设备

官方 iOS / macOS App 的远程推送需要 V2Echo Pro；请先在接收设备解锁或恢复购买，再生成配对码。助手未取得有效配对发送凭据时不会提交 S2S 事件或查询回执。配对码只用于临时兑换，成功配对后即使配对码过期，已保存的发送凭据仍可用于原绑定，直到被撤销、替换或失效。

先点击「添加账号」，选择连接方式并填写 V2EX API Token 和同账号 Cookie，再点击「验证并保存账号」；从账号选择器进入该账号的「连接与设置」。在接收设备的通知设置中生成配对码，再将其填入助手的「配对接收设备」，使用固定服务地址完成配对。首次配对需要同账号 Cookie（已在设置中保存时可复用），内容为含 A2 的单行 Cookie 请求头。助手仅访问 V2EX 首页，对照顶栏登录账号与 API 账号，不打开通知列表，不执行已读操作。Cookie 加密保存在当前服务器；普通模式仅发送至 V2EX 首页，浏览器模式按 V2EX 域使用 Cookie 并加载首页所需资源，不写日志或传给推送服务；失效后在设置中更新，留空保持原值。

成功后助手自动保存专属发送凭据；配对结果未知时可在有效期内用同一码重试。首次提醒由后续定时检查读取网页及 API 后创建，不在配对时另发一条。重新配对保留上次推送的 API 首条 ID，并停止旧连接的待处理事件；其他账号不受影响。移除后重新添加视为新配置。普通旧版逐条通知仍受服务端配对时间过滤，网页汇总表示本轮观察到的总数，可包含配对前尚未阅读的消息。

推送服务确认发送凭据失效或已撤销后，该账号显示「需重新配对」，暂停自动检查、凭据巡检与推送，手动检查也不可用。暂停状态在重启和普通设置保存后保留，其他账号不受影响。在 App 中生成新配对码，并到「连接与设置 → 接收设备」重新配对；成功后按原同步开关、推送时段与现有额度恢复。已提交给 APNs 的消息无法撤回。

## 查看已保存设置

登录管理页后，进入「连接与设置」或「网络代理」会回填当前账号保存的配置。个人 API Token、网页 Cookie、完整代理地址和配对生成的发送 Token 均可显示／隐藏或复制；敏感字段默认遮蔽，切换账号或退出会卸载当前表单，不保存到浏览器本地存储。

API Token、Cookie 和代理地址可直接编辑，留空保存仍保留原值；发送 Token 只读，由重新配对更新。保存后读取服务器实际保存的值，状态轮询不覆盖正在编辑的草稿。配对码仅用于临时兑换，不保存可回显的原码，需要从 App 重新生成。

浏览器前进、后退和刷新会恢复账号与页面。推送历史的搜索、状态、分页及详情页也保存在 Hash 查询参数中。登录后返回原链接；已移除账号的链接显示提示，不会自动打开另一账号的配置。

凭据与同步偏好分别保存，同一账号的工作台页面间切换会保留尚未保存的草稿；刷新、切换账号或进入账号管理会丢弃草稿。管理密钥、Token 和 Cookie 不写入 URL 或浏览器本地存储。

## 运行时网络代理

在账号的独立「网络代理」标签页中选择连接方式并保存。代理设置单独保存，不提交「连接与设置」中的草稿。设置只作用于当前账号，统一用于 V2EX API、定期 Cookie 首页检查，以及推送服务的配对、批量上报和回执；其他账号不受影响。

- **使用环境变量代理**（默认）：遵循运行进程的 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`（及小写形式），按 Go 标准库规则选择代理与绕过目标。环境变量在进程启动前设置，更改后重启。
- **直接连接**：忽略环境变量代理。
- **自定义 HTTP / HTTPS 代理**：所有上述请求使用指定代理，不使用 `NO_PROXY` 绕过；代理失败时不自动回退直连。

地址示例：`http://192.168.1.100:7890` 或 `https://proxy.example.com:8443`。需要认证时使用 `http://user:password@proxy.example.com:8080`，用户名 / 密码中的特殊字符使用 URL 百分号编码。地址不支持路径、查询参数或片段。`http://` / `https://` 表示连接代理服务器时使用的协议，二者均可通过 CONNECT 转发 HTTPS 目标。HTTPS 代理及目标站点仍执行正常证书校验，不提供跳过验证选项。

完整代理地址（包含认证信息）加密保存在当前账号配置中，状态接口只返回去掉用户名和密码的地址；登录后的设置页可回填完整地址并显示、复制，代理连接错误仍不暴露完整地址。已保存后留空保持不变，重新输入不带认证的地址可移除认证；切换到直连或环境变量模式并保存会删除原自定义代理地址。

保存后下一次网络请求使用新设置，旧空闲连接池会关闭；切换代理不会重置 API 额度、错误退避或 S2S 冷却，也不会替换设备绑定或重发旧队列。即使账号使用不同代理，实例仍共用同一保守的 V2EX API 额度预算。

「测试连接」使用当前填写的连接方式，无需先保存；自定义地址留空时使用该账号已保存的地址。测试并行访问 V2EX 首页与 V2Echo 官方推送服务健康检查接口，各自最多等待 8 秒，显示 HTTP 状态和响应耗时。HTTP 403 等表示已连接到站点但站点拒绝请求；测试不验证 Token 或设备配对。请求不携带 V2EX Cookie、PAT 或推送凭据，不跟随重定向，也不提交事件或查询回执。同一账号同时只进行一次连接测试；完成或取消后可立即重试，无固定冷却。测试不改变 API 额度与 S2S 冷却。

Docker 构建代理与运行时代理独立：[源码构建](deployment.md#从源码构建)中的 Compose `build.args` 不会自动设置容器运行环境。可直接使用管理页的自定义代理；选择环境变量模式时，需在容器的 `environment` 中另行提供变量。Docker 内的 `127.0.0.1` 是容器自身；使用宿主机或局域网代理时，填写容器能访问的地址，并让代理监听可访问的网卡。
## 首页 403 与浏览器验证

已保存账号的首页检查遇到 403 或 Cloudflare 挑战时，工作台显示“首页访问需要验证”。403 不等于 Cookie 过期，也不保证一定有验证码可解。部署方式见[NAS 浏览器验证](deployment.md#nas-浏览器验证)。

1. 保存代理后点击“打开验证窗口”。窗口访问使用已保存设置，未保存的代理草稿不生效。
2. 在新窗口中手动完成 V2EX 的访问验证；实际浏览器运行在 NAS，手机或电脑只是远程操作。不要切换账号。
3. 返回管理页点击“验证完成，重试首页”。助手重新加载首页，并校验顶栏账号与未读数；只有真实读取成功才恢复。
4. 之后首页沿用浏览器会话。再次遇到挑战时重新操作；“关闭兼容模式”清除该账号浏览器会话并恢复普通请求。

验证窗口每次有效 10 分钟；可重新打开续期。刷新管理页后也可点击“验证完成，重试首页”；窗口过期时需重新打开。一次只能验证一个账号，等待人工操作时不会被其他账号的检查切走。打开窗口和验证重试属于用户主动恢复操作，可在同步关闭或休息时执行；它们不查询通知 API、不发送提醒、不改变推送基准或 API 冷却。验证成功后，正常同步仍遵守启用开关、推送时段和原检查计划。

匿名“测试连接”仍使用普通 HTTP 请求且不携带 Cookie，因此浏览器验证成功后该测试仍可能显示 403，应以账号首页检查结果为准。


## 推送与休息时段

在「连接与设置 → 同步偏好」按账号设置每天允许推送的时段。新账号及未配置时段的旧账号默认 **UTC+8 的 08:00–24:00**，即 00:00–08:00 休息；不随浏览器或服务器时区变化。支持分钟精度、跨午夜（例如 22:00–次日 08:00）和显式「全天运行」。开始时间包含在时段内，结束时间不包含；24:00 仅可作结束时间，开始与结束相同须改选全天运行。

休息期间不发起自动网页检查、通知 API 检查、凭据巡检或推送服务通信（包括回执查询），不消耗检查额度，也不生成跳过记录。手动「立即检查」与新建测试推送同样暂停；读取记录、编辑设置、用户主动添加账号／验证配对及代理测试不受影响。进行中的请求在时段结束时取消，已提交的消息无法撤回，设备仍可能稍后显示。

恢复后按正常调度检查最新未读，再决定普通待发送事件的上报；原有冷却、共享额度、错误退避及事件有效期继续生效，不补跑休息期间错过的检查。过期事件不重新发送，尚未尝试上报的旧网页汇总在最新未读为零时跳过。同步总开关关闭后，到达开始时间也不会自动启用。

## 检查与提醒规则

每轮先读取 V2EX 首页未读数：为 0 时不请求通知 API，也不推送；大于 0 时，在额度允许后读取 API 第一页。只有首条消息 ID 与上次安排推送的 ID 不同（或尚无基准），才创建一条未读汇总。只改变未读数不触发提醒，删除首条消息则可能触发。助手不执行已读操作。

汇总显示本轮网页未读数，不是 API 返回条数或本地差值；网页与 API 是先后读取的快照，送达时未读数可能已变化。网络错误不视作 0 未读。完整去重、有效期和旧模式兼容规则见 [同步契约](synchronization.md#网页与-api-联合检查)。

详见 [同步契约](synchronization.md)。各账号默认期望检查周期为 180 秒，可分别调整；账号轮流获得检查机会。所有账号的 API 请求（包括身份验证与旧模式历史翻页）经过同一持久化额度控制，429 暂停共享出口请求，Token 失效只暂停对应账号。

S2S 按账号对应的配对设备独立调度：空闲后首轮立即上报，此后至少间隔 3 分钟；每轮最多 4 条事件与 16 条回执，无待处理事项时不通信。更改 V2EX 检查周期不改变上报间隔，重启、修改配置与重新配对不清除等待时间。服务端执行设备与全服务每日预算，429 使整条连接等待，APNs 故障按回执退避。管理页显示下次允许上报时间；具体默认额度见 [S2S 协议](s2s-protocol.md)。

## 推送测试

在「推送测试」中向当前已配对的 App 发送测试。需要账号验证通过、启用同步与上报、推送凭据未失效，并处于允许推送时段。标题为 `@用户名`，正文固定为“这是一条 V2Echo 测试推送，收到此消息说明推送已到达设备。”，不支持自定义文案。测试不会抓取 V2EX、创建真实通知或改变同步基线。

测试进入正常发送队列，有效期 15 分钟，遵守原有上报冷却、错误退避和服务预算。每账号三分钟最多创建一条测试，上一条未过期且仍待处理时不能再建；冷却持久化，重启或重新配对不会清零。网络结果未知时重试同一请求编号不会创建第二条测试。最近结果在测试页自动刷新，完整内容和时间保留在「推送历史」。APNs 接收回执与设备显示不同，请在 App 端确认测试文案；App 前台位于通知页时会抑制横幅。

推送服务必须支持 S2S 的 `test` 类型，升级时先更新推送服务，再更新助手。旧服务会因未知事件类型拒绝包含测试的整批请求。当前格式 4 数据库自动增补测试调度表，无需清空数据。历史自定义服务配置不会被静默改写，使用固定服务前应重新配对。

## 检查记录

独立「检查记录」页面展示当前账号实际发起的通知检查，按检查顺序倒序排列。每个账号在自己的 SQLite 中仅保留最近 50 条，写入新记录时自动删除超出的最早记录；重启保留，移除账号时一并清除。升级时自动创建记录表，既有检查不会补录。

记录包含检查起止时间、手动或自动触发、总耗时、网页未读数、网页与 API 各阶段的结果及耗时、API 首条 ID、推送基准和本轮上报决定。网页未读数为 0 与未获取（显示“—”）分开表示；网页成功但 API 等待额度、冷却或确认失败时显示“部分完成”。旧版 API 分页同步也会记录，但不将 API 返回条数当成网页未读数。等待调度、凭据验证、代理测试和配对不计入通知检查记录。手动检查遵守已有冷却，在实际发起检查时记录触发方式。

支持“全部 / 需要关注”筛选及行内详情，筛选与展开项保存到 Hash 查询参数，支持刷新与前进后退。每 5 秒读取本地记录；展开详情时保留当前列表并提示新记录。刷新列表不发起上游请求。记录不含凭据、请求地址或上游响应正文；加入上报队列不表示 APNs 接收或设备送达，后续结果见推送历史。

## 推送历史

选中账号后打开「推送历史」，查看进入上报队列的普通通知、网页未读汇总和测试事件，包括待处理、APNs 已接收、拒绝、过期、跳过与凭据失效的记录。支持按状态筛选、按通知标题 / 摘要 / 编号搜索，每页 20 条，可翻页查看更早记录；页面每 5 秒更新当前页，刷新最新记录可回到第一页。首次导入但未安排推送的历史通知仍在「通知记录」中查看。

列表展示本地保存的上报摘要和首次上报尝试时间。展开详情可查看通知产生时间、加入队列时间、最近同步尝试、服务端首次确认及结果记录时间；同步次数包含提交与回执查询。时间由助手所在服务器记录，回执结果时间不是 Apple 实际接受或设备送达的时间；APNs 已接收不证明设备已显示。详情中的提醒模板仅为当前规则的参考，实际手机展示由推送服务与设备决定。

历史保存在当前账号的 SQLite 中，重启、更换代理或重新配对均保留；移除该账号时一并清除。查看历史只读取本地数据库，不向推送服务请求，不改变额度或触发重发。当前格式 4 的数据库升级会自动增补历史计时表，不需要清空数据；旧记录原有的摘要与状态仍可查看，未曾记录的时间显示为“未记录”，不会用通知产生时间代替。

网页汇总保留观察时的未读数量和 API 首条 ID，ID 只在本地供核对，不上传推送服务。通知记录页展示实际同步的记录，不推定已读状态。暂停会同时暂停同步和上报。旧模式普通通知有效期为产生后 24 小时，离线积压过期后停止上报但保留本地历史。

通知与事件记录不自动清理。通过「账号管理 → 移除账号」可停止该账号任务，删除其凭据、同步状态、历史及队列；其他账号不受影响。备份中的副本需自行管理，接收设备上的远程连接仍可在 App 中关闭。事件记录参与去重，不应直接修改数据库。
