# 通知同步契约

## 数据与身份

数据来源为 `https://www.v2ex.com/api/v2/`，使用 Bearer PAT。请求不跟随重定向，不把 PAT 转发到其他服务。首次或 Token 更新后读取 `member` 验证身份；每条通知的 `for_member_id` 必须匹配当前账号。失效 Token 只暂停对应账号，避免不断重试。每个配置有独立数据库与加密密钥，历史、基线、高水位、错误退避及上报队列不跨账号；全局索引确保同一 V2EX member ID 只有一个有效配置。

SQLite 的通知主键为 `(account_id, notification_id)`，保存原始 JSON 与供管理页显示的纯文本。正文不在浏览器以 HTML 执行。ID 使用 Go `int64` 和 SQLite INTEGER。

## 网页与 API 联合检查

配置 Cookie 后，以 V2EX 首页未读数为唯一计数来源；Cookie 使用账号密钥 AES-GCM 加密，仅发送至首页。校验顶栏登录账号，不访问网页通知列表或执行已读操作。管理页只返回是否配置 Cookie，不返回原值，也不推定单条消息的已读状态。

每轮先读首页：0 未读不读通知 API，不推送；正数未读在额度允许后读取 API 第一页，首条 ID 与上次推送入队的 `last_push_api_id` 不相等才创建一个 `unread_summary`。计数取本轮网页值，API 总条数不参与判断；删除首条记录也会触发 ID 变化。没有基准时首次正数创建汇总，0 不重置基准。页内 ID 必须有效且严格倒序，收件账号必须匹配。网页与 API 非原子快照，空 API 或校验失败时保留基准并报错退避。

首页间隔至少三分钟，持久化 `next_web` 防止手动检查绕过退避或 Retry-After；API 检查仍遵守账号与实例额度。通知第一页、网页快照、首条 ID 基准及事件同事务提交，失败回滚；每个有效变化生成随机稳定事件 ID，支持 A→B→A，网络重试复用原事件。基准代表已安排发送，不代表 APNs 已接受或用户已阅读。

0 未读或新汇总取代旧汇总时，跳过尚未尝试发送的旧汇总。已尝试但结果未知的事件不修改，继续幂等重试；已提交的继续查询回执。只有计数变化时不创建新事件，原事件保留其观察时间与计数。汇总 15 分钟过期，过期或永久失败不会自动重建相同 ID 快照，需等待下一次首条 ID 变化。

配对完成后由此检查流程安排首次汇总。重新配对保留比较基准；原通知历史仍保存，当前模式不分页追补全部历史。旧版本未存 Cookie，补充配置前继续以下 API 模式。 启用 Cookie 时会跳过尚未尝试发送的旧模式通知，已经尝试但结果未知或等待回执的记录继续原有处理。

## 未配置 Cookie 的旧模式：首次导入

1. 第一页成功返回时，记录其中最大的通知 ID 为基线 `anchor_id`。空列表基线为 0。
2. 从第 1 页依次读取 API 当前可访问的历史通知并保存。重复 ID 合并；不根据总数变化判断增量。
3. 每页数据和下一页进度在同一个 SQLite 事务中提交。失败保留当前页，重启从已保存的位置继续。
4. 以响应的 `Notifications x-y/total` 范围或空列表识别末页；无法识别范围时继续读取，直到空列表。
5. 导入结束后从第一页补扫。ID 大于首次基线的通知生成上报事件，包含导入过程中产生的通知；基线及更早记录永不因首次导入推送。

“全部历史”指 API 当前允许访问的记录。官方没有快照分页协议：翻页期间新增、删除导致位置变化时，单次遍历不能提供数据库快照级完整性保证。唯一键解决重叠记录，补扫解决基线之后的新通知；要验收历史完整性，需在通知相对稳定时对照上游总量与记录。此版本不声称能恢复已删除或 API 不再暴露的通知。

## 未配置 Cookie 的旧模式：增量周期

从第一页读取，直到覆盖上次完整周期的 `high_water` 或到达末页。一页全是新增就继续翻页。整个周期的旧边界固定；新最大 ID 仅在周期完成后推进，不能把本轮已写入的第一页当作下次翻页的停止点。

通知插入、稳定事件创建、翻页状态共同提交。事件 ID 由账号 ID 与通知 ID 确定，重复抓取不会创建第二个事件。历史阶段不会创建事件；补扫和增量阶段为大于基线的记录 `INSERT OR IGNORE` 创建事件，即使它曾在历史翻页期间被保存。

此快速停止算法依赖“通知 ID 随新事件递增、API 按 ID 倒序返回”的假设，官方文档未明确承诺这一行为。代码验证页内倒序以及跨页向更早 ID 推进，失败时保留进度并报错，不静默继续；迟到的较小 ID 不在当前增量算法的完整性保证范围内。

## 动态额度

读取 `X-Rate-Limit-Limit`、`X-Rate-Limit-Remaining`、`X-Rate-Limit-Reset`，仅接受三者完整且合理的值。额度可能按出口 IP 共享，整个实例以 `accounts.db` 中的持久化预算统一限流，不给每个 PAT 分配完整额度。只有共享窗口允许请求时才推进账号轮转，避免固定轮转与额度间隔重合导致账号饥饿；同步与上报使用独立轮转。

预留窗口总额度的 10%，每次请求的最小间距为：

```text
可用次数 = 剩余次数 - 预留次数
请求间距 = max(10 秒, 剩余窗口时间 / 可用次数)
```

可用次数不足则等到 reset 后再请求。增量周期完成后的下一次检查还要满足用户设置的期望间隔；历史翻页不等待完整检查周期，但仍满足请求间距。手动检查不绕过额度与错误退避。

缺少有效响应头时采用本地 600 次 / 小时的保守预算并同样保留 10%；预算在发送请求之前落盘。任一账号收到 429 时所有账号至少等待 `Retry-After` 和已知额度窗口中较晚的时间。网络、5xx、403 或验证页面按指数退避，不把错误当成“没有通知”。本地计数无法控制同出口的其他程序，收到新的有效响应头后以服务器值校正。

## 推送服务通信

S2S 使用独立于 V2EX API 的调度状态。每个账号的 `relay_schedule` 在请求前与事件尝试次数一起提交，保存下一轮时间、连续失败次数与凭据阻塞状态；配置与配对操作不清除冷却。没有到期事件或回执时不请求推送服务，队列新到事件不能绕过当前等待。

每轮合并最多 4 条上报和 16 条回执；新事件与回执分别取队列，避免彼此饥饿。首轮立即，后续至少 180 秒并加入小幅随机延迟。连接失败影响整条连接；单条已接收事件的长退避只影响该事件，不阻塞其他新增事件。额度、错误与有效期的完整契约见 [S2S v1](s2s-protocol.md)。

## 出站代理

每个账号可选择环境变量、直连或自定义 HTTP/HTTPS 代理，三个出站客户端共用该账号的独立连接池。请求时读取持久化配置，代理变化后关闭旧空闲连接；不跨账号共享认证代理连接。配置更新沿用同步与推送锁，已在执行的请求完成后才切换。代理地址通过账号加密密钥保存，状态接口只暴露无 userinfo 的地址。

HTTP CONNECT 的代理认证与目标站点认证分离；代理失败不自动改用直连，仍进入原有失败处理与额度调度。独立代理配置接口只保存代理字段，保留账号凭据、同步状态、API 额度与上报等待时间；连接设置接口省略代理字段时保留原代理。

管理页的「测试连接」使用未保存的代理草稿创建独立临时连接池，并行 GET `https://www.v2ex.com/` 与 `https://app.v2echo.com/api/push/v1/health`，各自 8 秒超时，不跟随重定向；自定义地址留空则复用已保存地址。仅测试网络连通性，不携带账号认证、不调用 V2EX API、不提交事件或查询回执。返回 HTTP 状态与响应耗时，错误消息不包含代理认证信息。该手动操作有每账号每分钟一次的进程内限制，不修改持久化 API / S2S 预算，重启后可重新测试。

## 主动推送测试

管理接口 `POST /api/accounts/{accountID}/push-test` 接收 `event_id`，要求管理会话及请求来源校验。测试事件与每账号的 `push_test_schedule` 在同一事务提交，记录下一次允许创建时间和最近一次事件 ID；重复 ID 返回已保存的请求，不覆盖事件或重置冷却。状态接口的 `push_test` 只按最近事件 ID 读取本地结果，不触发远程查询。创建测试与配对、删除账号共用锁，连接更换时旧测试与其他待处理事件一起停止投递。

测试不访问 V2EX、不改同步阶段或通知基线。它沿用正常 S2S 队列、代理与回执调度；有效期、限额和文案见 [S2S v1](s2s-protocol.md)。管理页的常规设置保存只修改 V2EX 与同步配置，保留配对凭据；配对目标固定为官方服务，管理 API 拒绝手动覆盖地址或发送 Token。

## 本地推送历史

`outbox` 保留不可变的上报事件摘要与当前处理状态；`delivery_history` 记录助手观察到的入队、首次 / 最近同步尝试、服务端首次确认和终态时间。计时与事件写入在同一事务内提交，网络前预留尝试次数时同步记录时间；崩溃或失败回滚不会留下单独成功的历史记录。首次尝试可能对应结果未知的请求，终态时间是本地记录结果的时间，不代表 APNs 实际接受或设备送达。

格式 4 的已有数据库只增补计时表和相应记录入口，不改变队列或调度状态。旧事件通过原有 payload 读取内容，没有记录的时间保留未知；旧事件以后重试可记录最近尝试，但不会伪造首次尝试时间。账号移除清除队列及历史元数据。

管理接口 `GET /api/accounts/{accountID}/deliveries` 复用账号管理鉴权，只读本地数据。`limit` 默认为 20、最大 50；`before` 为上一页返回的 `next_cursor`，零表示最新页；`status` 为单个上报状态，省略时查询全部；`q` 为最多 200 字符的标题、摘要或编号字面搜索。结果按本地入队顺序倒序，返回 `items` 和 `next_cursor`，末页游标为零。状态可随回执变化，筛选页不保证跨请求快照。内容按纯文本显示，不执行 HTML。

## 源码入口

- `internal/assistant/accounts.go`：账号索引、隔离存储、移除与轮转。
- `internal/assistant/budget.go`：实例共享的请求预算。
- `internal/assistant/engine.go`：单账号同步阶段与错误状态。
- `internal/assistant/web_monitor.go`：网页计数与 API 首条 ID 联合检查。
- `internal/assistant/web_unread.go`：Cookie 首页校验与未读快照。
- `internal/assistant/quota.go`：窗口额度、预留与 Retry-After。
- `internal/assistant/store.go`：SQLite 事务、凭据加密、持久化事件。
- `internal/assistant/proxy.go`：代理地址校验、独立配置与连接测试、账号连接池及错误脱敏。
- `internal/assistant/relay.go`：批量上报与回执、连接冷却、持久化退避。
- `internal/assistant/history.go`：账号推送历史的分页、筛选与管理接口。
- `web/src/PushHistory.tsx`：推送历史、内容摘要与时间详情。

- `internal/assistant/push_test_event.go`：主动测试入队、幂等与持久化冷却。
- `web/src/PushTest.tsx`：测试条件、文案与最近结果。
