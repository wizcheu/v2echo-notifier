# 通知同步契约

[返回 README](../README.md) · [使用指南](user-guide.md)

## 数据与身份

网页模式由 V2EX 首页提供未读总数，以 `https://www.v2ex.com/api/v2/` 首条消息 ID 判断是否需要提醒；未配置 Cookie 的旧账号保留 API 同步模式。API 请求使用 Bearer PAT。请求不跟随重定向，不把 PAT 转发到其他服务。首次或 Token 更新后读取 `member` 验证身份；每条通知的 `for_member_id` 必须匹配当前账号。失效 Token 只暂停对应账号，避免不断重试。每个配置有独立数据库与加密密钥，历史、基线、高水位、错误退避及上报队列不跨账号；全局索引确保同一 V2EX member ID 只有一个有效配置。

SQLite 的通知主键为 `(account_id, notification_id)`，保存原始 JSON 与供管理页显示的纯文本。正文不在浏览器以 HTML 执行。ID 使用 Go `int64` 和 SQLite INTEGER。

## 账号与凭据状态

新增账号的 `POST /api/accounts` 必须提供 `api_token` 和 `cookie`；Cookie 经过单行、长度与 A2 校验，`proxy_mode` / `proxy_url` 经过与运行期相同的代理校验（默认 environment，自定义地址不可留空）。凭据与代理草稿仅在内存中用于同步验证：先请求 `/api/v2/member` 获取 `result.username`，再读取首页顶栏用户名，要求完全一致且区分大小写。整个验证最多等待 25 秒，两个请求使用同一代理策略、不跟随重定向；API 请求只携带 PAT，首页请求只携带 Cookie。无论是否已安装可选浏览器组件，仅 API 身份已确认且首页遭遇 403/CF 挑战的情况可保存为暂停同步的待网页验证账号（无网页验证时间、无未读快照）。尚未安装浏览器组件时显示安装引导；安装后需通过浏览器重试完成同账号校验，再继续配对和开启同步。其他验证失败仍不保存；仅共享 API 额度按实际请求保留。成功后加密保存凭据与代理、验证时间及网页快照，同时占用唯一 member ID；不创建推送或推进推送去重基准。旧配置继续保留，账号管理显示缺失 Cookie 的补充提示。

`token_issue` 与 `cookie_issue` 分别持久化：API 401 或明确的 Token invalid / expired / revoked 响应要求更新 Token；首页 401、V2EX 登录重定向、明确的登录入口且缺少登录身份、或账号不符要求更新 Cookie。普通网络错误、访问挑战和无法识别页面保持一般错误状态。已验证过身份的账号在 Token 失效后仍可检查 Cookie，但不请求通知 API 或创建推送；首次身份未知时需先更新 Token。凭据问题会暂停相应请求，修改对应凭据后清除此项问题，保留另一项问题及原有去重基准、额度和冷却。

`token_checked_at` / `cookie_checked_at` 表示最近成功检查时间。网页模式下，距离上次成功 API 检查 24 小时后使用只读 `GET token` 探测，复用共享额度并持久化请求预留；不读取或标记通知。网络失败退避后重试，Token 已失效则等待更新。未读为零或 Cookie 已失效也能触发该探测，账号暂停时不请求。常规通知 API 请求成功会顺延探测，因此不会对活跃账号重复检查。状态字段保存在已有 JSON 状态中，无需清空数据库。

账号列表返回验证状态、凭据配置标志和脱敏错误，不返回凭据。移除按账号清除本地数据并持久化删除标记；其他账号继续运行。

## 网页与 API 联合检查

配置 Cookie 后，以 V2EX 首页未读数为唯一计数来源；Cookie 使用账号密钥 AES-GCM 加密；普通模式仅发送至首页，浏览器模式按 V2EX 域使用 Cookie 并加载首页资源。校验顶栏登录账号，不访问网页通知列表或执行已读操作。状态接口只返回是否配置 Cookie；已登录的设置页可通过独立配置接口读取原值。管理页不推定单条消息的已读状态。

每轮先读首页：0 未读不读通知 API，不推送；正数未读在额度允许后读取 API 第一页，首条 ID 与上次推送入队的 `last_push_api_id` 不相等才创建一个 `unread_summary`。计数取本轮网页值，API 总条数不参与判断；删除首条记录也会触发 ID 变化。没有基准时首次正数创建汇总，0 不重置基准。页内 ID 必须有效且严格倒序，收件账号必须匹配。网页与 API 非原子快照，空 API 或校验失败时保留基准并报错退避。

首页间隔至少三分钟，持久化 `next_web` 防止手动检查绕过退避或 Retry-After；API 检查仍遵守账号与实例额度。通知第一页、网页快照、首条 ID 基准及事件同事务提交，失败回滚；每个有效变化生成随机稳定事件 ID，支持 A→B→A，网络重试复用原事件。基准代表已安排发送，不代表 APNs 已接受或用户已阅读。

0 未读或新汇总取代旧汇总时，跳过尚未尝试发送的旧汇总。已尝试但结果未知的事件不修改，继续幂等重试；已提交的继续查询回执。只有计数变化时不创建新事件，原事件保留其观察时间与计数。汇总 15 分钟过期，过期或永久失败不会自动重建相同 ID 快照，需等待下一次首条 ID 变化。

配对完成后由此检查流程安排首次汇总。重新配对保留比较基准；原通知历史仍保存，当前模式不分页追补全部历史。旧版本未存 Cookie，补充配置前继续以下 API 模式。 启用 Cookie 时会跳过尚未尝试发送的旧模式通知，已经尝试但结果未知或等待回执的记录继续原有处理。

## 未配置 Cookie 的旧模式：首次导入

1. 第一页成功返回时，记录其中最大的通知 ID 为基线 `anchor_id`。空列表基线为 0。
2. 从第 1 页依次读取 API 当前可访问的历史通知并保存。重复 ID 合并；不根据总数变化判断增量。
3. 每页数据和下一页进度在同一个 SQLite 事务中提交。失败保留当前页，重启从已保存的位置继续。
4. 以响应的 `Notifications x-y/total` 范围或空列表识别末页；无法识别范围时继续读取，直到空列表。
5. 导入结束后从第一页补扫。ID 大于首次基线的通知生成上报事件，包含导入过程中产生的通知；基线及更早记录永不因首次导入推送。

“全部历史”指 API 当前允许访问的记录。官方没有快照分页协议：翻页期间新增、删除导致位置变化时，单次遍历不能提供数据库快照级完整性保证。唯一键解决重叠记录，补扫解决基线之后的新通知；要验收历史完整性，需在通知相对稳定时对照上游总量与记录。此版本不声称能恢复已删除或 API 不再暴露的通知。

## 未配置 Cookie 的旧模式：增量周期

从第一页读取，直到覆盖上次完整周期的 `high_water` 或到达末页。一页全是新增就继续翻页。整个周期的旧边界固定；新最大 ID 仅在周期完成后推进，不能把本轮已写入的第一页当作下次翻页的停止点。

通知插入、稳定事件创建、翻页状态共同提交。事件 ID 由账号 ID 与通知 ID 确定，重复抓取不会创建第二个事件。历史阶段不会创建事件；补扫和增量阶段为大于基线的记录 `INSERT OR IGNORE` 创建事件，即使它曾在历史翻页期间被保存。

此快速停止算法依赖“通知 ID 随新事件递增、API 按 ID 倒序返回”的假设，官方文档未明确承诺这一行为。代码验证页内倒序以及跨页向更早 ID 推进，失败时保留进度并报错，不静默继续；迟到的较小 ID 不在当前增量算法的完整性保证范围内。

## 每日推送时段

每天按固定 UTC+8 执行一个账号独立时段，默认 08:00–24:00；支持跨午夜及全天运行。开始包含、结束不包含。同步关闭或处于休息时段时不发起自动检查、凭据巡检、推送及回执查询；手动检查和新建测试同样受限。恢复时先检查最新未读，保留既有额度、退避、冷却和有效期，不补跑错过的轮次。用户操作与例外见 [推送与休息时段](user-guide.md#推送与休息时段)。

配置字段 `push_schedule` 为 `{"mode":"window","start":"08:00","end":"24:00"}`，`mode` 可为 `window` 或 `all_day`。`PUT /api/accounts/{id}/config` 未提交该字段时保留原值，凭据编辑不会重置时段；配置与重启前状态保存在账号自己的 SQLite。状态接口返回 `push_schedule_status`，包含固定时区、服务端当前时间、是否休息、下次开始及当前时段结束时间，供网页展示恢复提示。休息期间请求检查或新建测试返回 HTTP 409。

## 动态额度

读取 `X-Rate-Limit-Limit`、`X-Rate-Limit-Remaining`、`X-Rate-Limit-Reset`，仅接受三者完整且合理的值。额度可能按出口 IP 共享，整个实例以 `accounts.db` 中的持久化预算统一限流，不给每个 PAT 分配完整额度。只有共享窗口允许请求时才推进账号轮转，避免固定轮转与额度间隔重合导致账号饥饿；同步与上报使用独立轮转。

预留窗口总额度的 10%，每次请求的最小间距为：

```text
可用次数 = 剩余次数 - 预留次数
请求间距 = max(10 秒, 剩余窗口时间 / 可用次数)
```

可用次数不足则等到 reset 后再请求。增量周期完成后的下一次检查还要满足用户设置的期望间隔；历史翻页不等待完整检查周期，但仍满足请求间距。手动检查不绕过额度与错误退避。

缺少有效响应头时采用本地 600 次 / 小时的保守预算并同样保留 10%；预算在发送请求之前落盘。任一账号收到 429 时所有账号至少等待 `Retry-After` 和已知额度窗口中较晚的时间。网络、5xx、403 或验证页面按指数退避，不把错误当成“没有通知”。本地计数无法控制同出口的其他程序，收到新的有效响应头后以服务器值校正。

## 推送服务通信

S2S 使用独立于 V2EX API 的调度状态。每个账号的 `relay_schedule` 在请求前与事件尝试次数一起提交，保存下一轮时间、连续失败次数与凭据阻塞状态；配置与配对操作不清除冷却。没有到期事件或回执时不请求推送服务，队列新到事件不能绕过当前等待。

S2S 返回 HTTP 401 / 403 后，持久化 `relay_schedule.blocked`，同时暂停该账号的定时检查、凭据巡检与推送通信；手动检查返回 HTTP 409。暂停不修改同步开关，不生成检查记录，也不消耗检查额度。重启、普通配置保存和失败的配对不会解除暂停；成功兑换新发送凭据后解除，并沿用原有时段、额度、冷却与推送基准，旧连接待处理事件停止投递。

每轮合并最多 4 条上报和 16 条回执；新事件与回执分别取队列，避免彼此饥饿。首轮立即，后续至少 180 秒并加入小幅随机延迟。连接失败影响整条连接；单条已接收事件的长退避只影响该事件，不阻塞其他新增事件。额度、错误与有效期的完整契约见 [S2S v1](s2s-protocol.md)。

## 出站代理

每个账号可选择环境变量、直连或自定义 HTTP/HTTPS 代理，三个出站客户端共用该账号的独立连接池。请求时读取持久化配置，代理变化后关闭旧空闲连接；不跨账号共享认证代理连接。配置更新沿用同步与推送锁，已在执行的请求完成后才切换。代理地址通过账号加密密钥保存，状态接口只暴露无 userinfo 的地址。

HTTP CONNECT 的代理认证与目标站点认证分离；代理失败不自动改用直连，仍进入原有失败处理与额度调度。独立代理配置接口只保存代理字段，保留账号凭据、同步状态、API 额度与上报等待时间；连接设置接口省略代理字段时保留原代理。

管理页的「测试连接」使用未保存的代理草稿创建独立临时连接池，并行 GET `https://www.v2ex.com/` 与 `https://app.v2echo.com/api/push/v1/health`，各自 8 秒超时，不跟随重定向；自定义地址留空则复用已保存地址。仅测试网络连通性，不携带账号认证、不调用 V2EX API、不提交事件或查询回执。返回 HTTP 状态与响应耗时，错误消息不包含代理认证信息。同一账号同时只进行一次连接测试，完成或取消后可立即重试，无固定冷却；不修改持久化 API / S2S 预算。

## 主动推送测试

管理接口 `POST /api/accounts/{accountID}/push-test` 接收 `event_id`，要求管理会话及请求来源校验。测试事件与每账号的 `push_test_schedule` 在同一事务提交，记录下一次允许创建时间和最近一次事件 ID；重复 ID 返回已保存的请求，不覆盖事件或重置冷却。状态接口的 `push_test` 只按最近事件 ID 读取本地结果，不触发远程查询。创建测试与配对、删除账号共用锁，连接更换时旧测试与其他待处理事件一起停止投递。

测试不访问 V2EX、不改同步阶段或通知基线。它沿用正常 S2S 队列、代理与回执调度；有效期、限额和文案见 [S2S v1](s2s-protocol.md)。管理页的常规设置保存只修改 V2EX 与同步配置，保留配对凭据；配对目标固定为官方服务，管理 API 拒绝手动覆盖地址或发送 Token。

## 管理接口与账号隔离

管理密钥可访问此实例的全部账号，账号选择器用于管理配置，不是不同管理员的权限隔离。管理接口均显式携带配置 ID：`GET /api/accounts`、`POST /api/accounts`、`DELETE /api/accounts/{id}`，以及 `/api/accounts/{id}/status`、`config`、`pair`、`check`。新增接口 `POST /api/accounts` 必须包含非空 `api_token` 与含 A2 的 `cookie`，可同时提交 `proxy_mode` 与 `proxy_url`（默认使用环境变量代理，自定义模式必须填写地址）；服务端同步验证 API 与网页身份，成功保存后才返回 201。不存在隐式默认账号。

## 已保存配置读取

`GET /api/accounts/{accountID}/config` 返回当前账号解密后的配置，复用管理会话、请求校验头与来源检查，响应禁止缓存。设置页按需请求；状态轮询仍只返回凭据配置标志和脱敏代理地址。前端将保存值回填，Token、Cookie、代理地址默认遮蔽并可显示、复制，发送 Token 只读。保存时仅提交当前表单可编辑字段，不把读取到的发送凭据用于覆盖配对。

配置保存在当前账号表单内存中，切换账号或退出后卸载；轮询不覆盖草稿，代理与连接设置分别回填保存结果。读取只访问本地存储，不触发上游请求或修改额度。

## 本地检查记录

`GET /api/accounts/{accountID}/check-history` 通过管理会话与来源校验后读取当前账号最近 50 条实际检查记录。`check_history` 写入时按本地 ID 删除超出保留数量的旧记录；休息时段，以及仅等待额度而未实际发起请求的轮次不补录；网页已读取而 API 等待额度时仍记录本次观察。字段包含起止时间、触发方式、网页与 API 阶段、观察值及上报决定；缺失未读数使用 null，与 0 区分。记录不包含凭据、请求地址或上游响应正文。用户展示规则见 [检查记录](user-guide.md#检查记录)。

## 本地推送历史

`outbox` 保留不可变的上报事件摘要与当前处理状态；`delivery_history` 记录助手观察到的入队、首次 / 最近同步尝试、服务端首次确认和终态时间。计时与事件写入在同一事务内提交，网络前预留尝试次数时同步记录时间；崩溃或失败回滚不会留下单独成功的历史记录。首次尝试可能对应结果未知的请求，终态时间是本地记录结果的时间，不代表 APNs 实际接受或设备送达。

格式 4 的已有数据库只增补计时表和相应记录入口，不改变队列或调度状态。旧事件通过原有 payload 读取内容，没有记录的时间保留未知；旧事件以后重试可记录最近尝试，但不会伪造首次尝试时间。账号移除清除队列及历史元数据。

管理接口 `GET /api/accounts/{accountID}/deliveries` 复用账号管理鉴权，只读本地数据。`limit` 默认为 20、最大 50；`before` 为上一页返回的 `next_cursor`，零表示最新页；`status` 为单个上报状态，省略时查询全部；`q` 为最多 200 字符的标题、摘要或编号字面搜索。结果按本地入队顺序倒序，返回 `items` 和 `next_cursor`，末页游标为零。状态可随回执变化，筛选页不保证跨请求快照。内容按纯文本显示，不执行 HTML。

## 源码入口

- `internal/assistant/accounts.go`：账号索引、隔离存储、移除与轮转。
- `internal/assistant/budget.go`：实例共享的请求预算。
- `internal/assistant/engine.go`：单账号同步阶段与错误状态。
- `internal/assistant/push_schedule.go`：UTC+8 每日时段校验、边界判断及状态。
- `internal/assistant/check_history.go`：最近 50 条检查记录及管理接口。
- `internal/assistant/credentials.go`：低频 Token 检查及凭据验证时间。
- `web/src/AccountManager.tsx`：账号管理、移除确认及凭据更新入口。
- `internal/assistant/web_monitor.go`：网页计数与 API 首条 ID 联合检查。
- `internal/assistant/web_unread.go`：Cookie 首页校验与未读快照。
- `internal/assistant/quota.go`：窗口额度、预留与 Retry-After。
- `internal/assistant/store.go`：SQLite 事务、凭据加密、持久化事件。

## 可选浏览器首页读取

普通首页请求收到 HTTP 403 或 `cf-mitigated: challenge` 时持久化恢复提示，不将其当成 Cookie 过期。管理接口 `POST /api/accounts/{accountID}/browser/{start,check,disable}` 复用管理登录、同源和请求头校验。`start` 使用当前账号代理和 Cookie 准备浏览器窗口，`check` 在同一活动浏览器重新加载首页并复用现有身份/计数解析，`disable` 清理会话并恢复普通请求。打开过验证窗口的账号后续首页使用浏览器，无静默 HTTP 回退；API 与推送保留原通道。

浏览器恢复状态及 Cookie 保存在账号 `browser_session` 表，整个记录使用账号密钥加密，状态接口仅返回可用、启用、需要验证三个标志。代理或登录 Cookie 变化前撤销活动窗口并清除旧浏览器凭据；账号移除清除浏览器记录和活动会话。浏览器处于其他账号人工验证租期内时，首页检查保留基准并等待后续重试。手动重试成功只更新首页快照及 Cookie 验证状态，清除网页退避，不推进推送基准、API 额度或上报冷却。

源码入口：`internal/assistant/browser.go`（加密状态、会话租期、恢复及桌面代理）、`browser/bridge.py`（Chromium 首页与代理连接）、`web/src/BrowserVerification.tsx`（验证入口）。桌面仅转发像素与输入，HTML 通过私有控制接口返回 Go 解析，不作为管理页 HTML 渲染。
