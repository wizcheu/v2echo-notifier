# V2Echo 通知助手

基于 React、Go 和 SQLite 的自托管通知助手，由 V2EX 首页提供未读总数、API v2 首条消息 ID 判断是否需要提醒，并通过 HTTPS 上报汇总事件。所有网络请求均由助手主动发起，无需公网入站地址。

## 功能

- Web 管理页：登录、账号管理与凭据异常提醒、Token / Cookie 与 HTTP/HTTPS 代理配置、账号验证、同步状态与上报记录。
- 通知检查：网页未读数为准，API 首条消息 ID 与上次推送不同才提醒一次；额度调度和去重基准保存在 SQLite。
- 事件上报：遵循 [S2S v1 协议](docs/s2s-protocol.md)，支持通知与回执批量同步、持久化冷却和幂等重试。
- 推送服务固定为 `https://app.v2echo.com/api/push`，通过接收设备提供的配对码配置发送凭据；未配对时仍可运行本地同步。
- 一个实例最多管理 20 个 V2EX 账号，每个账号独立保存 PAT、历史、同步进度、发送凭据和事件队列。账号名来自 API 身份验证，同一 V2EX 账号不能重复添加；替换 PAT 必须仍属于原账号。

## 本地开发

需要 Go 1.26、Node.js 22.12+ 和 npm。

```sh
git clone https://github.com/wizcheu/v2echo-notifier.git
cd v2echo-notifier
make build
./bin/notifier
```

默认仅监听 `127.0.0.1:8282`。启动后读取本地管理密钥，再打开 `http://127.0.0.1:8282` 登录：

```sh
./bin/notifier -print-admin-token
```

服务日志只显示密钥文件的位置，不显示密钥本身。首次创建的密钥保存在 `data/admin-token`；管理会话只存于浏览器的 HttpOnly、SameSite=Strict Cookie，12 小时过期，程序重启后需重新登录。

开发 React 时，在另一个终端执行：

```sh
cd web
npm run dev
```

Vite 把 `/api` 代理到本地 Go 服务。React 构建产物通过 `go:embed` 打入正式可执行文件；修改前端后重新执行 `make build`。

## Docker

```sh
docker compose up -d --build
docker compose exec notifier /notifier -data /data -print-admin-token
```

如果下载 Go 依赖超时，可通过 `GOPROXY` 指定可访问的模块镜像，例如 [Goproxy.cn](https://goproxy.cn/)：

```sh
GOPROXY=https://goproxy.cn,direct docker compose up -d --build
```

也可在 Compose 同目录的 `.env` 中设置 `GOPROXY=https://goproxy.cn,direct`，以后直接执行 `docker compose up -d --build`。未设置时使用 Go 官方代理；模块校验保持启用。该设置只影响 Go 构建阶段的模块下载。

构建期间的 `npm ci` 和 `go mod download` 可通过 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 使用代理。Compose 从当前终端或同目录 `.env` 读取这些值，并作为 Docker 的预定义构建参数传入。例如，将下面的示例地址替换为构建容器可访问的 HTTP 代理地址：

```sh
HTTP_PROXY=http://192.168.1.100:7890 \
HTTPS_PROXY=http://192.168.1.100:7890 \
docker compose up -d --build
```

代理运行在另一台电脑上时，需允许局域网访问，并使用该电脑的局域网 IP；构建容器中的 `127.0.0.1` 指向容器自身。`HTTPS_PROXY` 的值可使用 `http://`，表示通过 HTTP 代理隧道访问 HTTPS。这些参数用于构建步骤；拉取基础镜像所需的代理应另行配置到 Docker daemon 或 BuildKit，运行中的服务也不自动继承构建代理。详见 [Docker 构建代理参数](https://docs.docker.com/build/building/variables/#proxy-arguments)。

默认使用 Docker 命名卷持久化 `/data`，通过 `8282:8282` 将容器端口发布到宿主机，可在局域网访问 `http://<宿主机地址>:8282`。也可通过 SSH 转发访问：

```sh
ssh -L 8282:127.0.0.1:8282 user@your-server
```

也可在用户自己的 HTTPS 反向代理后运行，并设置 `ECHO_SECURE_COOKIE=true`。代理需保留原 Host；接口校验 Origin 与自定义请求头。不要把未加密的管理接口直接暴露到公网。

根目录 `data/accounts.db` 保存账号索引与共享请求额度；每个账号的数据存入 `data/accounts/<随机配置ID>/notifier.db`，PAT、网页 Cookie 与推送凭据使用该目录下的 `encryption.key` 做 AES-GCM 加密。此加密不防止拿到整个数据目录的攻击者；备份必须保护整个卷，凭据文件不应加入源码或日志。单个数据目录只运行一个助手进程。当前账号数据库格式为 4，不自动转换旧开发版数据库；格式不兼容时请使用新的数据目录。

## 账号管理与凭据提醒

通过侧栏「账号管理」查看所有已添加账号的启用状态、Token / Cookie 验证状态和错误，进入「连接与设置」更新凭据，或确认移除旧账号。移除会删除该账号的本地凭据、历史与推送队列，不删除 V2EX 网站账号，也不影响其他配置。删除后的账号不会在服务重启后恢复；备份中的副本需另行管理。

新建账号必须同时填写 API Token 和 Cookie，管理页与服务端均校验必填。前往 [V2EX Token 设置](https://v2ex.com/settings/tokens) 生成令牌，Scope 选择 Everything，有效期建议 180 天；可用 Scope 和有效期见 [官方 API 文档](https://www.v2ex.com/help/api)。Cookie 需包含 A2。添加时先选择环境变量代理、直连或自定义 HTTP/HTTPS 代理，再点击「验证并保存账号」。助手使用所选连接方式请求 `/api/v2/member`，将 `result.username` 与 Cookie 对应的首页顶栏用户名逐字比较（区分大小写）；完全一致且首页可正常读取后，才一起加密保存凭据和代理设置。验证失败、账号不匹配、请求取消或 API 额度冷却时不创建账号，修改表单或等待冷却后可重试。旧账号不被删除，未配置 Cookie 的会显示补充提示。

API 返回 Token 过期或失效时，工作台与账号管理显示更新提醒，暂停该账号的自动 API 请求；Cookie 返回未登录首页、登录跳转、401 或账号不匹配时，单独提示更新 Cookie，并暂停首页检查。网络失败、403 访问挑战或无法识别的页面显示访问错误并退避，不直接判为 Cookie 过期。两种问题独立保存，重启不清除；已验证过身份的账号在 Token 失效后仍会检查 Cookie，便于同时发现两项问题；更新对应凭据后重新验证，保留原推送基准、历史和冷却。

没有通知 API 请求的账号，每 24 小时用只读 `GET token` 检查 Token；正常通知请求成功会顺延这项检查。检查仍遵守账号与实例额度、Retry-After，Cookie 失效期间也可检查 Token。提醒以实际检查结果为准，不提供精确到期倒计时；暂停账号时停止后台检查。页面每五秒刷新已有检查状态，不因浏览页面额外请求上游。

## 查看已保存设置

登录管理页后，进入「连接与设置」或「网络代理」会回填当前账号保存的配置。个人 API Token、网页 Cookie、完整代理地址和配对生成的发送 Token 均可显示／隐藏或复制；敏感字段默认遮蔽，切换账号或退出会卸载当前表单，不保存到浏览器本地存储。

API Token、Cookie 和代理地址可直接编辑，留空保存仍保留原值；发送 Token 只读，由重新配对更新。保存后读取服务器实际保存的值，状态轮询不覆盖正在编辑的草稿。配对码仅用于临时兑换，不保存可回显的原码，需要从 App 重新生成。

`GET /api/accounts/{id}/config` 仅供已登录的设置页读取解密后的配置，需要 `X-V2Echo-Request: 1` 和同源请求；响应为 `Cache-Control: no-store`。常规状态轮询仍只返回凭据是否配置及脱敏代理地址。配置读取不访问 V2EX 或推送服务，也不改变调度和配额。

## 运行时网络代理

在账号的独立「网络代理」标签页中选择连接方式并保存。代理设置单独保存，不提交「连接与设置」中的草稿。设置只作用于当前账号，统一用于 V2EX API、定期 Cookie 首页检查，以及推送服务的配对、批量上报和回执；其他账号不受影响。

- **使用环境变量代理**（默认）：遵循运行进程的 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`（及小写形式），按 Go 标准库规则选择代理与绕过目标。环境变量在进程启动前设置，更改后重启。
- **直接连接**：忽略环境变量代理。
- **自定义 HTTP / HTTPS 代理**：所有上述请求使用指定代理，不使用 `NO_PROXY` 绕过；代理失败时不自动回退直连。

地址示例：`http://192.168.1.100:7890` 或 `https://proxy.example.com:8443`。需要认证时使用 `http://user:password@proxy.example.com:8080`，用户名 / 密码中的特殊字符使用 URL 百分号编码。地址不支持路径、查询参数或片段。`http://` / `https://` 表示连接代理服务器时使用的协议，二者均可通过 CONNECT 转发 HTTPS 目标。HTTPS 代理及目标站点仍执行正常证书校验，不提供跳过验证选项。

完整代理地址（包含认证信息）加密保存在当前账号配置中，状态接口只返回去掉用户名和密码的地址；登录后的设置页可回填完整地址并显示、复制，代理连接错误仍不暴露完整地址。已保存后留空保持不变，重新输入不带认证的地址可移除认证；切换到直连或环境变量模式并保存会删除原自定义代理地址。

保存后下一次网络请求使用新设置，旧空闲连接池会关闭；切换代理不会重置 API 额度、错误退避或 S2S 冷却，也不会替换设备绑定或重发旧队列。即使账号使用不同代理，实例仍共用同一保守的 V2EX API 额度预算。

「测试连接」使用当前填写的连接方式，无需先保存；自定义地址留空时使用该账号已保存的地址。测试并行访问 V2EX 首页与 V2Echo 官方推送服务健康检查接口，各自最多等待 8 秒，显示 HTTP 状态和响应耗时。HTTP 403 等表示已连接到站点但站点拒绝请求；测试不验证 Token 或设备配对。请求不携带 V2EX Cookie、PAT 或推送凭据，不跟随重定向，也不提交事件或查询回执。每个账号每分钟可手动测试一次，测试不改变 API 额度与 S2S 冷却。

Docker 构建代理与运行时代理独立：前述 Compose `build.args` 不会自动设置容器运行环境。可直接使用管理页的自定义代理；选择环境变量模式时，需在容器的 `environment` 中另行提供变量。Docker 内的 `127.0.0.1` 是容器自身；使用宿主机或局域网代理时，填写容器能访问的地址，并让代理监听可访问的网卡。

## 配对接收设备

先点击「添加账号」，选择连接方式并填写 V2EX API Token 和同账号 Cookie，再点击「验证并保存账号」；从账号选择器进入该账号的「连接与设置」。在接收设备的通知设置中生成配对码，再将其填入助手的「配对接收设备」，使用固定服务地址完成配对。首次配对需要同账号 Cookie（已在设置中保存时可复用），内容为含 A2 的单行 Cookie 请求头。助手仅访问 V2EX 首页，对照顶栏登录账号与 API 账号，不打开通知列表，不执行已读操作。Cookie 加密保存在当前服务器，仅发往 V2EX 首页，不写日志或传给推送服务；失效后在设置中更新，留空保持原值。

成功后助手自动保存专属发送凭据；配对结果未知时可在有效期内用同一码重试。首次提醒由后续定时检查读取网页及 API 后创建，不在配对时另发一条。重新配对保留上次推送的 API 首条 ID，并停止旧连接的待处理事件；其他账号不受影响。移除后重新添加视为新配置。普通旧版逐条通知仍受服务端配对时间过滤，网页汇总表示本轮观察到的总数，可包含配对前尚未阅读的消息。

## 网页未读与提醒规则

1. 每轮先读取首页；未读为 0 时不请求通知 API、不推送，也不重置上次推送的首条 ID。
2. 未读大于 0 时，在额度允许后只请求 API 第一页。将首条消息 ID 与上次已入推送队列的首条 ID 比较：相同则不推送，不同（或尚无基准）则只创建一条汇总。
3. 文案为 `@用户名` / `你有 N 条未读提醒，打开应用查看`，N 取本轮网页值，不是 API 返回条数或本地差值。只改变未读数而首条 ID 不变，不触发提醒。
4. 删除 API 首条消息也可能改变首条 ID，因此会再提醒一次；删除其他记录不会因总数变化触发。网页与 API 是先后读取的两个快照，不能提供原子一致性保证。

比较基准与事件在同一 SQLite 事务入队，重启不重置。发送失败重试同一事件，不重新创建；这里的“上次推送”指已安排推送，不要求 APNs 回执或用户阅读。每个汇总有效期 15 分钟；网页未读变为 0 或新的首条 ID 创建了汇总时，会跳过尚未尝试发送的旧汇总。已尝试发送且结果未知的事件保持原内容重试，已提交的继续查询回执。仅计数变化时保留已入队的观察快照，送达时计数可能已变化；过期或永久拒绝可在推送历史查看。

网页访问失败、账号不符、计数缺失，或正数未读但 API 暂无记录时，保留推送基准并退避，不把失败当成 0。首页检查至少间隔三分钟，手动检查也遵守首页冷却和 Retry-After；API 与 S2S 各自遵守额度和冷却。notifier 不维护每条消息的已读状态。

旧安装没有保存 Cookie；升级后需在「连接与设置」补充 Cookie 才启用上述模式。未配置 Cookie 时保留 API 历史导入和逐条增量提醒。启用网页模式后只保存实际读取到的 API 第一页，保留原本地历史，不再分页补齐全部历史。先升级支持 `unread_summary` 的推送服务，再更新助手。 启用 Cookie 时会跳过尚未尝试发送的旧模式通知，已经尝试但结果未知或等待回执的记录继续原有处理。

## 同步与调度

详见 [同步契约](docs/synchronization.md)。各账号默认期望检查周期为 180 秒，可分别调整；账号轮流获得检查机会。所有账号的 API 请求（包括身份验证与旧模式历史翻页）经过同一持久化额度控制，429 暂停共享出口请求，Token 失效只暂停对应账号。

S2S 按账号对应的配对设备独立调度：空闲后首轮立即上报，此后至少间隔 3 分钟；每轮最多 4 条事件与 16 条回执，无待处理事项时不通信。更改 V2EX 检查周期不改变上报间隔，重启、修改配置与重新配对不清除等待时间。服务端执行设备与全服务每日预算，429 使整条连接等待，APNs 故障按回执退避。管理页显示下次允许上报时间；具体默认额度见 [S2S 协议](docs/s2s-protocol.md)。

## 推送测试

在「推送测试」中向当前已配对的 App 发送测试。需要账号验证通过、启用同步与上报、推送凭据未失效。标题为 `@用户名`，正文固定为“这是一条 V2Echo 测试推送，收到此消息说明推送已到达设备。”，不支持自定义文案。测试不会抓取 V2EX、创建真实通知或改变同步基线。

测试进入正常发送队列，有效期 15 分钟，遵守原有上报冷却、错误退避和服务预算。每账号三分钟最多创建一条测试，上一条未过期且仍待处理时不能再建；冷却持久化，重启或重新配对不会清零。网络结果未知时重试同一请求编号不会创建第二条测试。最近结果在测试页自动刷新，完整内容和时间保留在「推送历史」。APNs 接收回执与设备显示不同，请在 App 端确认测试文案；App 前台位于通知页时会抑制横幅。

推送服务必须支持 S2S 的 `test` 类型，升级时先更新推送服务，再更新助手。旧服务会因未知事件类型拒绝包含测试的整批请求。当前格式 4 数据库自动增补测试调度表，无需清空数据。历史自定义服务配置不会被静默改写，使用固定服务前应重新配对。

## 推送历史

选中账号后打开「推送历史」，查看进入上报队列的普通通知、网页未读汇总和测试事件，包括待处理、APNs 已接收、拒绝、过期、跳过与凭据失效的记录。支持按状态筛选、按通知标题 / 摘要 / 编号搜索，每页 20 条，可翻页查看更早记录；页面每 5 秒更新当前页，刷新最新记录可回到第一页。首次导入但未安排推送的历史通知仍在「通知记录」中查看。

列表展示本地保存的上报摘要和首次上报尝试时间。展开详情可查看通知产生时间、加入队列时间、最近同步尝试、服务端首次确认及结果记录时间；同步次数包含提交与回执查询。时间由助手所在服务器记录，回执结果时间不是 Apple 实际接受或设备送达的时间；APNs 已接收不证明设备已显示。详情中的提醒模板仅为当前规则的参考，实际手机展示由推送服务与设备决定。

历史保存在当前账号的 SQLite 中，重启、更换代理或重新配对均保留；移除该账号时一并清除。查看历史只读取本地数据库，不向推送服务请求，不改变额度或触发重发。当前格式 4 的数据库升级会自动增补历史计时表，不需要清空数据；旧记录原有的摘要与状态仍可查看，未曾记录的时间显示为“未记录”，不会用通知产生时间代替。

网页汇总保留观察时的未读数量和 API 首条 ID，ID 只在本地供核对，不上传推送服务。通知记录页展示实际同步的记录，不推定已读状态。暂停会同时暂停同步和上报。旧模式普通通知有效期为产生后 24 小时，离线积压过期后停止上报但保留本地历史。

通知与事件记录不自动清理。通过「连接与设置 → 移除账号」可停止该账号任务，删除其凭据、同步状态、历史及队列；其他账号不受影响。备份中的副本需自行管理，接收设备上的远程连接仍可在 App 中关闭。事件记录参与去重，不应直接修改数据库。

管理密钥可访问此实例的全部账号，账号选择器用于管理配置，不是不同管理员的权限隔离。管理接口均显式携带配置 ID：`GET /api/accounts`、`POST /api/accounts`、`DELETE /api/accounts/{id}`，以及 `/api/accounts/{id}/status`、`config`、`pair`、`check`。新增接口 `POST /api/accounts` 必须包含非空 `api_token` 与含 A2 的 `cookie`，可同时提交 `proxy_mode` 与 `proxy_url`（默认使用环境变量代理，自定义模式必须填写地址）；服务端同步验证 API 与网页身份，成功保存后才返回 201。不存在隐式默认账号。
